# Stock Ledger

仿 [TradingView Portfolios](https://cn.tradingview.com/portfolios/) 的股票买卖记录与收益率统计（Vue3 + FastAPI + MySQL + global-stock-data）。

## 环境要求

- Node.js 20.19+ 或 22.12+
- Python 3.12+
- MySQL 8（当前环境已安装本机服务 `MySQL84`；也可改用 `docker compose up -d`）

## 快速启动

### 1. 数据库

默认连接（见 `backend/.env`）：

```
mysql+pymysql://stock:stockledger123@127.0.0.1:3306/stock_ledger
```

root 密码同为 `stockledger123`。样例数据导入：

```bash
cd backend
python scripts/seed_csv.py
```

### 2. 后端

```bash
cd backend
pip install -r requirements.txt
python -m uvicorn app.main:app --reload --port 8000
```

### 3. 前端

```bash
cd frontend
npm install
npm run dev
```

打开 http://localhost:9999 。前端通过 Vite 代理访问 `http://127.0.0.1:8000` 的后端；接口文档位于 http://127.0.0.1:8000/docs 。样例 CSV 已导入；也可在「交易」页重新上传 `sample-data/Code_20260726.csv`（全量替换）。

> 说明：样例 CSV 仅有 Buy/Sell、无 Deposit，因此现金会为负值（与 TradingView 导入同类数据表现类似）。可在交易页补一条「入金」记录。点击「刷新行情」会通过 global-stock-data 的新浪/腾讯数据源同步美股最新价（请求失败时保留数据库缓存）。

## 功能概览

- 概览：净值曲线、时间区间收益、每日赢家/输家
- 持股：持仓 / 清仓 / 累计、市场情绪、信号与指标趋势
- 策略：资金配置、交易纪律和下单清单
- 复盘：交易复盘、当前持仓处理、清仓再买入、历史回测
- 交易：CRUD、CSV 导入导出、股息 Tab
- 分析：投资组合 / QQQ / 标普500 / 3个月美债 / 黄金 / 比特币 / 汇率的月度分组柱状图、累计盈亏

主菜单固定在顶部，市场切换和主题按钮位于右侧，移动端市场标签简写为“美 / A / 港”。账户金额卡片只在概览展示，随页面滚动，不固定在顶部。主题默认随时钟切换，手动切换后保留选择；持股页的市场卡片、图表与弹窗跟随当前主题。持仓表的信号列居中，点击信号单元格会直接打开该标的的指标趋势，包括未触发信号的持仓。

持股页顶部统一展示市场情绪、阿姆士、指数走势及 A 股大盘资金信息，不再重复显示“市场信息”标题；原价格页已移除，旧 `/prices` 地址跳转到 `/holdings`。指标趋势入口位于下载图片左侧，保留当前持仓和已清仓标的，不受持股表的分页、搜索或子页签影响。

策略导航只保留策略汇总、资金配置、交易纪律和下单清单，移动端仅显示当前选中的内容。复盘的标题与说明位于页面顶部，子页签、统一日期范围和刷新数据按钮位于同一工具栏。交易复盘、持仓处理、清仓再买入和历史回测共享日期范围；切换日期会清空旧回测结果，点击工具栏的“刷新数据”才运行回测，清空日期则使用全部已有日线。

指标趋势表按交易日展示收盘、日涨跌、开高低、昨收、成交量/额、触发信号、锚定日和技术指标。日涨跌及仓位上限由该日历史日线计算，分页首行也使用库中前一根日线。历史资金流、组合平价、PE 和 ERP 尚未保存，相关列显示 `—`，不使用当前数据填充历史记录。

## 分析基准口径

五项基准直接展示在“投资组合盈利能力”的月度分组柱状图，与投资组合和 QQQ 使用相同的实际起止日。首月从区间内第一条净值开始，后续月份从前一个月末净值开始，首尾不足整月按实际日期计算；响应包含年份和实际起止日，避免跨年同名月份混淆。月度净值统一截至最近一个已完成的 UTC 自然日，不混入当日未完成数据。基准先计算日累计收益，再用起止累计净值之比折算各月收益，不直接相减；缺少端点时该柱留空。

标普500优先读本地 `.inx` 指数日线，缺失时从新浪补取价格指数（不含股息）；黄金使用新浪 `GLD` 黄金 ETF 的美元价格作为代理，界面明确标记“GLD ETF代理”，不冒充现货金价；比特币使用 Kraken `BTC/USD` 的 UTC 日收盘价（公开接口最多提供最近 720 根，已有缓存继续保留）。资产基准按美元计价，未计税费；组合柱沿用本币账本净值变动（包含出入金），并标记 USD / CNY / HKD。柱图仅用于对照，不自动换汇，也不把净值变化当成剔除出入金后的纯策略收益。

无风险对照采用美国财政部公开日利率 CSV 的 `3 Mo` 年化利率，按月并行补取。每个自然日使用前一日或更早已发布的利率，按“年化利率 ÷ 365”逐日复利折算同期收益；这是假设利率滚动再投资的估算，不是美债市价涨跌，也不是将年化利率直接作为区间收益。超过 7 天没有有效利率时停止计算并留空，不使用后来发布的利率回填。

汇率使用 ECB 经 Frankfurter API 发布的 USD/CNY 参考汇率（1 美元可兑换的人民币，不是银行成交价）。默认取倒数计算 CNY/USD 的各月变化，正值代表人民币升值、美元贬值；可切换为 USD/CNY，正值代表美元升值、人民币贬值。汇率在柱图中作为独立系列，不用于转换其他资产的收益。

基准按需获取已完成的真实报价，保存到 `daily_bar` 的独立 `BENCH:*` 键；不创建持仓、不扩大监控、不写入虚构 OHLC，也不把休市沿用值存成新日线。已覆盖区间优先读数据库，缺失时并行补取，外部失败有 15 分钟重试冷却。缺少区间起点的数据不改用较晚日期归一化，缺少交易日报价显示空缺或 `—`，不会伪装成零收益。

## 回测数据

回测和指标趋势仅允许当前持仓或有清仓记录的标的，观察名单不参与。A 股和美股普通股票的回测、回测 K 线及指标趋势的已收盘历史日线统一读取全市场数据库 `market_symbol` / `market_bar` 的前复权 OHLCV，不为普通股票历史日线请求外部行情。ETF（包括 SPY 对照）及港股继续使用原来的 `daily_bar` 日线缓存和数据源。指标趋势的最新页仍可追加当日未收盘的实时日线，A 股午休也保留当日行情；实时日线不落库，普通股票收盘后不会用实时行情替代缺失的历史日线。

旧版 `market_bar` 只有收盘价。后端启动和回填命令会添加开盘、最高、最低价字段；已有股票历史需补齐真实 OHLC 后才能回测或查看指标趋势，缺失时会显示错误，不用收盘价代替，也不退回旧日线源。指标缓存会在历史更新、交易日切换及收盘后失效。可在 `backend` 目录运行：

```bash
python -m app.services.market_bars backfill --market us --ohlc --symbols NASDAQ:INTC NASDAQ:RKLB --no-rebuild
python -m app.services.market_bars backfill --market cn --ohlc --symbols SSE:601012 SSE:600362 --no-rebuild
```

省略 `--symbols` 并加上 `--no-list`，可补齐该市场库中所有股票的 OHLC；回填会保留原历史起始日期。新增已收盘快照也会保存真实 OHLC。

## 收盘日线归档

独立的后台日线归档线程会自动补存持仓和已清仓的 ETF、港股等非全市场日线源标的，不依赖全市场扫描，也无需打开回测或指标趋势页面。按交易所日历确认收盘后，从原日线数据源取得已完成的 OHLCV 并持久保存到 `daily_bar`；开盘中、午休和盘前不会冻结当日数据，节假日不会制造新日线。已保存的同日记录不重复写入，也不因清仓而删除。

数据源尚未发布收盘日线或请求失败时，每 10 分钟重试；后端重启后也会补齐缺少的已收盘历史。新增归档会使对应的旧指标页缓存失效，以便读取最终收盘数据。归档不发送钉钉提醒，分钟指标监控仍只覆盖当前持仓。此功能需要后端持续运行；普通股票仍由全市场库的收盘快照和回填流程维护，本归档任务不为它们另存一份 `daily_bar`。

## A 股持仓初始化

在 `backend` 目录运行 `python scripts/seed_cn_positions.py` 预览价格页标的的建仓计划，加 `--apply` 才写入本地账本。每只预算 25,000 元，以最近已收盘交易日的收盘价为成本，数量向下取整到 100 股；ETF 读取原日线缓存，普通股票读取全市场数据库，不请求外部行情。缺少该日收盘价或预算不足一手时停止，不写入部分计划。

脚本在写入前将该组合的交易记录备份至 `backend/data/`，已有买卖记录的标的不重复建仓，也不修改美股交易、净值缓存或出入金记录。初始化手续费为零，成交日期使用收盘价日期。
